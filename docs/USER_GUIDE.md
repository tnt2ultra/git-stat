# Руководство пользователя Git stat

## 1. Назначение руководства

Это руководство описывает, как запустить Git stat, импортировать реестр сервисов, выбрать ветку, запустить синхронизацию и интерпретировать статистику.

---

## 2. Требования

Перед запуском необходимо:

- установленный JDK 25;
- установленный Maven 3.9+;
- установленный нативный `git`;
- доступ к корпоративному GitLab;
- GitLab access token с правом `read_repository`.

Проверить Git:

```bash
git --version
```

---

## 3. Настройка переменных окружения

### Linux или macOS

```bash
export GITLAB_TOKEN=ваш_токен_read_repository
export GITLAB_ALLOWED_HOST=gitlab.corp.example
```

### Windows PowerShell

```powershell
$env:GITLAB_TOKEN="ваш_токен_read_repository"
$env:GITLAB_ALLOWED_HOST="gitlab.corp.example"
```

Где:

- `GITLAB_TOKEN` — токен для чтения репозиториев;
- `GITLAB_ALLOWED_HOST` — разрешённый хост GitLab.

---

## 4. Сборка и запуск

### Сборка

```bash
mvn clean package
```

### Запуск

```bash
java -jar target/git-stat-0.0.1-SNAPSHOT.jar
```

или:

```bash
mvn spring-boot:run
```

После запуска откройте:

```text
http://localhost:8080
```

---

## 5. Подготовка CSV-реестра

Файл должен быть в кодировке UTF-8.

Разделитель — точка с запятой.

Первая строка — заголовок.

Пример:

```csv
"название группы";"название сервиса";"url репозитория в корпоративном GitLab"
"compare";"db-compare";"https://gitlab.corp.example/compare/db-compare.git"
"compare";"pg-compare";"https://gitlab.corp.example/compare/pg-compare.git"
```

Обязательные колонки:

```text
название группы
название сервиса
url репозитория в корпоративном GitLab
```

Требования к URL:

- только HTTPS;
- хост должен совпадать с `GITLAB_ALLOWED_HOST`;
- URL не должен содержать логин, пароль или токен;
- желательно заканчиваться на `.git`.

---

## 6. Импорт CSV через интерфейс

1. Откройте главную страницу.
2. В левой колонке найдите блок «Импорт реестра».
3. Нажмите выбор файла и укажите CSV.
4. Нажмите «Импортировать выбранный CSV».
5. Дождитесь результата.

При успехе будет показан JSON вида:

```json
{
  "groupsCreated": 1,
  "servicesCreated": 2,
  "servicesUpdated": 0,
  "errors": []
}
```

При ошибке будет показан список проблемных строк.

Важно: импорт строгий. Если есть хотя бы одна ошибка, не импортируется ни одна строка.

---

## 7. Импорт catena.csv

Если в проекте есть файл:

```text
src/main/resources/catena.csv
```

то в блоке «Импорт реестра» доступна кнопка:

```text
Импортировать catena.csv
```

Кнопка активна только если файл найден в classpath.

Для работы файла после сборки убедитесь, что он попал в JAR. Если вы изменили `catena.csv`, пересоберите проект:

```bash
mvn clean package
```

---

## 8. Выбор ветки анализа

В правой колонке находится блок «Синхронизация».

Доступный выбор:

- по умолчанию;
- develop;
- develop-spimex;
- master;
- main;
- Ввести вручную.

Если выбрано «Ввести вручную», появится поле для имени ветки.

Примеры допустимых ручных имён:

```text
feature/my-branch
bugfix/JIRA-123
release/1.2.3
```

Некорректные имена:

```text
my branch
-feature
release//1.2.3
release.lock
```

---

## 9. Запуск синхронизации

### Синхронизация всех сервисов

Нажмите:

```text
Синхронизировать все сервисы
```

Система последовательно обработает все сервисы из реестра.

Для каждого сервиса будет создана задача синхронизации.

### Синхронизация одного сервиса

В таблице «Сервисы» нажмите кнопку:

```text
Синхронизировать
```

в нужной строке.

---

## 10. Просмотр задач синхронизации

После запуска в блоке «Задачи синхронизации» отображаются:

- ID;
- сервис;
- статус;
- начало;
- окончание;
- количество коммитов;
- количество файлов;
- ошибка.

Возможные статусы:

- SUCCESS;
- FAILED.

Если выбрана ветка, которой нет в репозитории, задача будет FAILED с сообщением:

```text
Ветка не найдена в репозитории: develop
```

---

## 11. Интерпретация статистики

### 11.1. Сводка

Показывает:

- количество групп;
- количество синхронизированных сервисов;
- суммарный код в строках;
- суммарные тесты в строках;
- общее количество строк;
- отношение тестов к коду.

### 11.2. Группы

Показывает агрегаты по каждой группе сервисов.

Колонки:

- Группа;
- Сервисов;
- Код, строк;
- Тесты, строк;
- Всего;
- Тесты/код.

### 11.3. Сервисы

Показывает каждый сервис:

- Группа;
- Сервис;
- Ветка;
- Код, строк;
- Тесты, строк;
- Статус;
- Действие.

Колонка «Ветка» показывает ветку, по которой был сделан последний успешный снимок.

### 11.4. Сотрудники

Показывает агрегированную commit-based статистику по авторам:

- Имя;
- Email;
- Коммитов;
- Добавлено кода;
- Удалено кода;
- Добавлено тестов;
- Удалено тестов;
- Сервисов.

Важно:

- это статистика по изменениям в коммитах, а не по текущему владению строками;
- merge-коммиты исключены;
- generated и migration файлы исключены;
- разные email одного человека считаются разными авторами.

## 14. Типичные проблемы

### 14.1. Не найден git

Симптом:

```text
error=2, No such file or directory
```

Причина:

- нативный `git` не установлен или не добавлен в `PATH`.

Решение:

```bash
git --version
```

Установите Git, если команда недоступна.

---

### 14.2. Ошибка клонирования

Возможные причины:

- неверный `GITLAB_TOKEN`;
- токен не имеет права `read_repository`;
- неверный `GITLAB_ALLOWED_HOST`;
- репозиторий недоступен;
- URL указан без `.git`;
- в URL есть учетные данные.

Решение:

1. Проверьте токен.
2. Проверьте хост.
3. Проверьте URL в CSV.
4. Попробуйте склонировать вручную:

```bash
git clone --bare https://gitlab.corp.example/group/service.git
```

---

### 14.3. Ошибка импорта CSV

Частые причины:

- неверный заголовок;
- разделитель не `;`;
- файл не UTF-8;
- пустые поля;
- дубликаты группы и сервиса;
- дубликаты URL;
- HTTP вместо HTTPS;
- чужой хост;
- URL с логином и паролем.

Откройте результат импорта в UI и найдите строку с ошибкой.

---

### 14.4. Кнопка catena.csv неактивна

Причины:

- файл `catena.csv` отсутствует в `src/main/resources`;
- файл не попал в JAR;
- приложение запущено из старой сборки.

Решение:

1. Положите файл:

```text
src/main/resources/catena.csv
```

2. Пересоберите:

```bash
mvn clean package
```

3. Перезапустите приложение.

---

### 14.5. Ветка не найдена

Сообщение:

```text
Ветка не найдена в репозитории: develop
```

Причина:

- выбранной ветки нет в конкретном репозитории.

Решение:

- выберите другую ветку;
- используйте «по умолчанию»;
- проверьте имя ветки;
- убедитесь, что ветка существует в GitLab.

---

### 14.6. Синхронизация SUCCESS, но строки равны нулю

Если commit-based статистика есть, а текущие строки равны нулю:

1. Проверьте, есть ли в ветке `.java`-файлы.
2. Включите DEBUG-лог:

```yaml
logging:
  level:
    com.anri.gitloc.service.GitAnalysisService: DEBUG
```

3. Посмотрите строку:

```text
Snapshot: ветка = ..., найдено Java-файлов = ..., посчитано строк для = ...
```

Если найдено 0 файлов, проверьте ветку и репозиторий вручную:

```bash
git -C ./git-repos/service-1/repo.git ls-tree -r HEAD
```

---

### 14.7. Ошибка null identifier ServiceLocSnapshot

Если после обновления кода появляется ошибка Hibernate:

```text
null identifier (com.anri.gitloc.domain.ServiceLocSnapshot)
```

скорее всего старая схема H2 осталась от предыдущей версии модели.

Решение:

1. Остановите приложение.
2. Удалите каталог:

```text
./data
```

3. Запустите приложение заново.

Альтернативно можно удалить только таблицу:

```sql
DROP TABLE IF EXISTS service_loc_snapshots;
```

и перезапустить приложение.

---

### 14.8. Ошибка блокировки H2

Если приложение уже запущено, второй экземпляр может не получить доступ к файловой базе.

Решение:

- остановите предыдущий процесс;
- или используйте `AUTO_SERVER=TRUE`, который уже задан в конфигурации.

---

## 15. Рекомендации по использованию

1. Начинайте с небольшого CSV на 2–3 сервиса.
2. Используйте «по умолчанию», если не уверены в названиях веток.
3. Для сравнения веток запускайте синхронизацию отдельно для каждой ветки и сохраняйте результаты вручную, так как история snapshot не хранится.
4. Следите за задачами синхронизации: ошибки по отдельным сервисам нормальны, если ветка отсутствует.
5. Не используйте H2 console и приложение в публичном доступе без дополнительной защиты.
6. Регулярно делайте резервную копию каталога `./data`, если реестр сервисов важен.

---

## 16. Что делать при изменении реестра

Если вы изменили CSV:

1. Импортируйте новый CSV.
2. Система выполнит upsert.
3. Сервисы, которых нет в новом CSV, не удаляются автоматически.
4. Если URL сервиса изменился, локальный кэш репозитория сбрасывается.
5. Запустите синхронизацию заново.

---

## 17. Краткая справка по метрикам

| Метрика | Смысл |
|---|---|
| Код, строк | Текущие строки продуктового Java-кода в ветке |
| Тесты, строк | Текущие строки Java-тестов в ветке |
| Тесты/код | Отношение тестов к коду |
| Коммитов | Количество коммитов автора, затронувших CODE или TEST |
| Добавлено кода | Строки, добавленные автором в CODE |
| Удалено кода | Строки, удалённые автором из CODE |
| Добавлено тестов | Строки, добавленные автором в TEST |
| Удалено тестов | Строки, удалённые автором из TEST |

---

## 18. Важные предупреждения

- Количество строк не равно качеству кода.
- Большое количество тестов не гарантирует хорошее покрытие.
- Commit-based статистика не показывает, кто владеет текущими строками.
- Статистика зависит от корректности классификации тестов и generated code.
- Сервис не предназначен для production-аналитики большого числа репозиториев.
